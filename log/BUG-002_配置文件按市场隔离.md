# BUG-002 | crypto 开发污染 A股共享配置文件

- **状态**：已修复（已归档）
- **修复提交**：`b2a2d14 [bug fix] BUG-002: 配置文件按市场隔离`
- **日期**：2026-07-18

## 1. 现象

win-debug 分支原本 A股全链路可跑通。新增加密货币功能（`feature/crypto-data`）后，A股开始报错，且**报的错与加密货币一样**。

## 2. 根因

提交 `5d05ebc [crypto] add: crypto prompt 适配`（2026-07-17）把差异内容直接写入了**共享配置文件**，未隔离到 crypto 专属文件：

| 文件 | win-debug（A股原版） | 5d05ebc 后被改成 |
|---|---|---|
| `experiment.yaml` | CSI300、SH600000、Test 到 2024-12-01 | 加了 "top-50 cryptocurrencies"、BTCUSDT、Test 到 2025 |
| `prompts.yaml`（`factors/prompts/`） | 11 处 "stock" 措辞 | 11 处改成 "asset" |
| `data_template/README.md` | A股数据描述 | crypto 数据描述 |

加载路径 `proposal.py` / `feedback.py` / `qlib_utils.py` 全部硬编码共享文件，不按市场区分 → A股读到 crypto 内容。

conf 文件（`conf_baseline.yaml` 等）反而是干净的：A股 / crypto 已分开。

## 3. 修复

A股文件 git 回退到 `5d05ebc~1`（被污染前），crypto 独立持有副本：

| 操作 | 文件 |
|---|---|
| 回退 | `experiment.yaml` → 纯净 A股 |
| 回退 | `prompts.yaml` → "stock" 措辞 |
| 回退 | `data_template/README.md` → A股数据描述 |
| **新建** | `prompts_crypto.yaml`（crypto "asset" 措辞） |
| **新建** | `README_crypto.md`（从 git 历史抢救的 crypto 数据描述） |
| 改动 | `market_config.py` +`get_prompts_file()` / +`get_readme_file()` |
| 改动 | `proposal.py`（2 处）+ `feedback.py`（2 处）→ 市场感知 |
| 改动 | `qlib_utils.py` → README 复制按市场切换 |

## 4. 验证

- 模拟 `MARKET_TYPE=a_stock`：experiment.yaml / prompts.yaml / README.md
- 模拟 `MARKET_TYPE=crypto`：experiment_crypto.yaml / prompts_crypto.yaml / README_crypto.md
- 全部 `py_compile` OK、工作树干净、推送 origin/feature/crypto-data

## 5. 与 BUG-001 的关系

配置污染 ≠ OOM。但 A股被喂了 crypto 提示后，LLM 会按 crypto 风格生成因子，可能**叠加**放大 BUG-001（to_parquet OOM malloc）触发概率。二者并列修复。
